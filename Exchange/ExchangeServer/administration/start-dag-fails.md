# Start-DatabaseAvailabilityGroup fails with BlockedDeserializeTypeException in Exchange Server Subscription Edition

## Summary

This article explains a known issue in Exchange Server Subscription Edition (SE) where the [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup) cmdlet fails in a [database availability group (DAG)](/exchange/high-availability/database-availability-groups/database-availability-groups) that's configured for [Datacenter Activation Coordination (DAC) mode](/exchange/high-availability/database-availability-groups/dac-mode). It describes the `BlockedDeserializeTypeException` error that causes the failure and provides workarounds to successfully reintegrate a stopped DAG member.

## Symptoms

In Exchange Server SE, when you configure a DAG for DAC mode, you might not be able to reintegrate a previously stopped DAG member by using the [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup) PowerShell cmdlet.

The issue occurs after you perform steps similar to the following:

```powershell
Set-DatabaseAvailabilityGroup \<DAGName\> -DatacenterActivationMode DagOnly

Stop-DatabaseAvailabilityGroup \<DAGName\> -MailboxServer \<ServerName\>
```

The cmdlet fails and logs Event ID 4999 in the Application event log.

```output
Microsoft.Exchange.Diagnostics.BlockedDeserializeTypeException:

Deserialization of type

System.Management.IWbemClassObjectFreeThreaded

blocked due to InDeny at location HaRpcError.
```

In some environments, the exception appears within a `System.AggregateException` that's generated by the `Start-DatabaseAvailabilityGroup` cmdlet.

## Cause

This issue occurs because the type `System.Management.IWbemClassObjectFreeThreaded` is in a deserialization block list. During execution of the [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup) cmdlet, Exchange attempts to deserialize information that includes this type, causing the operation to fail with `BlockedDeserializeTypeException`. You can't remove the object from the block list. The block list protection mechanism causes the failure.

## Workaround

Before you run [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup), manually add the stopped node by using one of the following methods and then start the DAG.

### Method 1: Add the cluster node

In Windows Server PowerShell, run the [Add-ClusterNode](/powershell/module/failoverclusters/add-clusternode) PowerShell cmdlet as shown in the following example:

```powershell
Add-ClusterNode \<ServerName\>
```

### Method 2: Add the DAG server

In Exchange PowerShell, run the [Add-DatabaseAvailabilityGroupServer](/powershell/module/exchangepowershell/add-databaseavailabilitygroupserver) cmdlet as shown in the following example:

```powershell
Add-DatabaseAvailabilityGroupServer -Identity &lt;DAGName&gt;-MailboxServer \<ServerName\>
```

### Start the DAG

After you add the server, run the [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup) as shown in the following example:

```powershell
Start-DatabaseAvailabilityGroup \<DAGName\>
```

The [Start-DatabaseAvailabilityGroup](/powershell/module/exchangepowershell/start-databaseavailabilitygroup) cmdlet succeeds after you use either [Add-ClusterNode](/powershell/module/failoverclusters/add-clusternode) or [Add-DatabaseAvailabilityGroupServer](/powershell/module/exchangepowershell/add-databaseavailabilitygroupserver) to reintroduce the stopped node.

## Status
Microsoft has confirmed this as a known issue. The product team is aware of the behavior and is evaluating potential improvements in a future update. Currently, no estimated timeframe for a resolution is available.
